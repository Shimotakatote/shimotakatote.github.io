The problem

Staff kept switching between their calendar, Asana, a customer lookup tool and Intercom all day. Time tracking was manual. You had to remember to start the Asana timer, and remember to stop it.

What I built

I took over an existing Chrome extension in October 2026. It is a Manifest V3 side panel with a Python backend on Cloud Run. While I owned it, it went from v0.3.1 to v0.3.56. The panel holds:

  • A calendar timeline that flashes red 2 minutes before a meeting.
  • "Time today", with a green, amber or red nudge.
  • Customer lookup with a "View as" option, plus email hover actions on any page.
  • An Asana card with play and stop buttons that drive Asana's own timer.
  • Intercom tickets and customer cards, an Ask Gemini box, and a day grid of the schedule.

Around it I set up CI-signed releases, a staging backend with feature flags, and Playwright end-to-end and screenshot tests. I also redesigned it to be calmer, with light, dark and auto themes and a bundled Inter font.

The Claude Code auto-timer

A lot of my work happens in Claude Code sessions. I wanted the Asana timer to follow the session without me touching it.

Five Claude Code hooks track which Asana task a session is on. The panel then starts and stops the real Asana timer, so the time lands in Asana like any other entry.

The obvious way to link a Chrome extension to a local program is native messaging. It kept failing, and I traced the failures to a Google Admin policy. So I wrote a small local HTTP service instead, using only Python's standard library. It listens on 127.0.0.1 only, checks the Origin and a request header, guards against DNS rebinding, and exits after 30 idle minutes. The hooks never block a turn. If the service is down, Claude Code carries on.

How it works

  1. Hooks report

    The hooks fire when a session starts, on each prompt, after each tool call, when Claude stops and when the session ends. They pass the session's current Asana task to the local service.

  2. The local service holds the state

    It keeps track of which task is active. It answers only on 127.0.0.1 and only to requests that pass its Origin and header checks.

  3. The panel reads it

    The side panel asks the local service what is running and shows it on the Asana card.

  4. Asana's timer runs

    The panel starts or stops Asana's own timer on that task. Nobody has to press play.

What changed

The panel shipped fast. It went from v0.3.1 to v0.3.56 while I owned it, between 12 October and 13 November 2026. Not every one of those releases was mine. Some of the November ones were shipped by a team agent on the shared repo. The timer work ran from v0.3.40 to v0.3.56.

On v0.3.56, all 218 end-to-end tests pass in CI. The Asana card went out to all staff on 15 October 2026. On 6 November I added the timer hook to the team's shared Claude Code setup, so others get it too.

Before

Four tools in four tabs. The Asana timer started and stopped by hand, when someone remembered.

After

One panel beside any page. For Claude Code work, the Asana timer follows the session on its own.
