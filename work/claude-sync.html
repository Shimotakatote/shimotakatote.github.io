claude-sync

A VS Code extension that syncs Claude Code sessions, skills and settings across devices through each user's own Google Drive.

Stack
TypeScript, VS Code Extension API, Google Drive API and OAuth (googleapis), chokidar, esbuild. Tests in Mocha with @vscode/test-electron.
Role
Personal project. I designed and built it.
Status
v2.5.4. Built in April 2026.
Numbers
  • v2.5.4 latest version
  • 47 tests
  • 23 commits over 3 days
  • 12 design specs and plans
  • ~4.7k lines of TypeScript and JavaScript

The problem

Claude Code keeps everything in one folder on your machine, ~/.claude. That folder holds your sessions, skills, commands, MCP server setup, hooks and settings. Each computer has its own copy. Move to another machine and none of it comes with you.

The first spec was for a team of three sharing one plan. Each of them wanted the same sessions and the same setup on every device they used. Copying the folder by hand does not work for long. It also copies things that should never leave the machine, like credentials.

What I built

claude-sync is a VS Code extension. It watches ~/.claude and syncs it through the user's own Google Drive, into the Drive app-data folder. That is a hidden folder only the extension can see, so it does not clutter anyone's Drive. There is also an optional push to a private GitHub repo.

It adds a sidebar with two tabs:

  • Sessions. Search your sessions, see live titles, continue one, rename it, delete it, or open the raw JSONL.
  • Setup. Every skill, command, hook and setting, with its sync state next to it.

There is also a Drive file manager. It can delete files in bulk, but only after three confirmations.

Before

Firestore

The first version synced through Firebase Firestore. That meant a database I had to host and pay for, holding everyone's files.

After

Your own Drive

Each user's files go to their own Google Drive. There is no server to run and no hosting bill.

How it works

  1. Sign in

    The user signs in with Google through OAuth. The extension asks for its own app-data folder in that user's Drive.

  2. Watch

    chokidar watches ~/.claude for new and changed files.

  3. Filter

    A hard-coded never-sync list keeps credential files on the machine. Before settings are uploaded, their env blocks are stripped out, because that is where people tend to put keys.

  4. Upload

    Changed files go up to the Drive app-data folder.

  5. Pull on the next device

    The same user signs in on another machine, and the extension brings their sessions and setup down into that machine's ~/.claude.

Safety

The extension writes files into a folder that Claude Code trusts, so I was careful about what it accepts.

  • Paths coming back from Drive are checked, so a synced file cannot write outside ~/.claude.
  • The sidebar is hardened against XSS, since it shows text that comes from session files.
  • Credential files are on a hard-coded never-sync list.
  • Bulk delete in the Drive file manager needs three confirmations.

What changed

Moving from Firestore to each user's own Drive was the big decision. It removed the hosting cost. It also means nobody's sessions sit in a database that someone else runs.

I designed it to scale to 50+ users with no servers. That is a design goal. It has not been run at that size.

The work happened in April 2026: 23 commits over 3 days, up to v2.5.4, with 47 tests. I wrote 12 design specs and plans along the way, including the one for the move to Drive.
