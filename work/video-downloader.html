Video Downloader v2

A Chrome extension that saves HLS and DASH streams as real MP4 files. It has its own demuxer and muxer, so it needs no other software.

Stack
JavaScript. Chrome Manifest V3: service worker, offscreen document, IndexedDB, declarativeNetRequest. Node test harness and Playwright.
Role
Personal project. I designed and built it.
Status
v2.0.0. Built on 14 October 2026.
Numbers
  • ~5.6k lines of JavaScript
  • 1 Claude Code session to build it
  • 4 formats: HLS, DASH, MP4, WebM

The problem

Most video on the web is not one file. Sites use HLS or DASH. The page loads a playlist, and the playlist points to hundreds of short segments. Audio and video are often separate.

So "save video as" gives you nothing useful. Joining the segments end to end gives you a .ts file, or a pile of fragments that many players cannot seek through. The usual fix is to copy the playlist URL into ffmpeg or yt-dlp on the command line. That works, but it is a lot to ask of someone who just wants the file.

What I built

A Manifest V3 Chrome extension. It spots HLS, DASH, MP4 and WebM media on the page and lists them in its popup. Pick one and it downloads the parts and rebuilds them into a single MP4 that plays and seeks in any normal player.

It also:

  • records live streams;
  • can pause, resume and retry a download without starting over;
  • copies a ready-made ffmpeg or yt-dlp command, for people who prefer the command line.

What it will not do

It detects DRM-protected streams and will not download them. It also refuses to run on major streaming sites. Both are on purpose. It is meant for streams you have the right to save.

How it works

  1. Detect

    The extension spots the playlists and media files a page loads, and works out which format each one is.

  2. Read the manifest

    It parses HLS playlists and DASH manifests. That includes DASH segment templates and timelines, multi-period DASH, byte ranges, and HLS discontinuities, where the stream changes partway through.

  3. Fetch

    The downloading runs in an offscreen document, not the service worker. Chrome stops an idle MV3 service worker, which would kill a long download. Progress is saved in IndexedDB, so a download can pause, resume or retry.

  4. Demux

    My own demuxer reads MPEG-TS and fragmented MP4 segments and pulls out the raw audio and video samples, with their timing.

  5. Mux

    My own MP4 muxer writes those samples into one file with a proper index, so players can jump to any point.

What changed

The result is a real, seekable MP4 from a stream, with no ffmpeg install and no command line. The demuxer and muxer are my own JavaScript.

I built it in one Claude Code session on 14 October 2026. The extension comes to about 5.6k lines of JavaScript. I tested it with a Node test harness and with Playwright driving a real browser.

The container code is the core of it. MPEG-TS and MP4 store the same audio and video in very different ways. Getting timestamps to line up across segments, discontinuities and separate audio is what makes the file seek properly.
